# ADR: Team IR 协作边界与克制原则

状态：已批准为本次 Team IR v2 落地任务的架构基线
范围：Team IR 根 Schema、编译器和 Runtime 的职责边界

## 背景

Team IR 需要表达真实分工中的委派、会签、条件参与、复核、汇总和返工，同时保持编译、运行和恢复语义可预测。常见替代方案是引入全局共享状态、动态节点掩码或更多 Join 模式；这些能力看似灵活，却会扩大状态所有权、权限和恢复规则的范围。

本 ADR 选择让团队拓扑保持静态，把条件表达在 Handoff 路由，把数据可见性表达在显式映射，并用类型合同和运行时状态记录实际发生的交接。

## 决策

### 显式交接，不开放可变 Blackboard

Agent 通过命名端口接收数据，通过输出信封交付结果。Run task 和 Run 字段有明确引用范围；除不可变 task 外，字段需经映射进入 Agent 输入。Artifact 使用调用范围的读取白名单。

这减少了对隐式状态树的耦合，使输入合同可检查、交付可审计，也降低无关中间产物影响下游判断的风险。Agent 仍是模型或工具驱动的非确定执行者，并非数学意义上的纯函数。

显式映射是数据最小化和审计机制，**不是保密性或非干扰保证**。所有 Agent 都能看到不可变 `$.run.task`；Team 作者也可以把任意允许的字段显式映射给角色。盲评、投标和博弈场景不得把秘密放入共享 task、公共 Artifact 或会泄露该信息的输出。需要强隔离时，应使用独立 Run、身份/信息流策略或密码学能力。

### 用局部条件路由表达裁剪

Team 拓扑在一个 Team 版本内静态定义；Handoff 的条件控制当前分支是否激活。v2 不支持运行时修改全局节点/边 mask。

局部条件能表达“此交接在当前上下文下是否发生”，但不等价于全局掩码：它不会自动禁用 Agent 的其它入边或出边，也不会绕过 Join、结果唯一写入和 Loop 预算规则。编译器因此可以按静态拓扑检查引用、端口、必填映射和可能冲突；运行期仍须处理条件求值、跳过来源和超时。

### 复用 `all_of` / `quorum_of` 与 Schema optionality

v2 不增加 `all_active`。`all_of` 等待所有来源确定为 `arrived` 或 `skipped`：必需贡献缺席即失败；只贡献 optional 字段/Artifact 的条件来源可以合法跳过，缺失值直接省略。目标至少需要一个实际到达来源，防止空 Join 触发 Agent。

`quorum_of` 固定按显式 threshold 判定；非保证到达来源只能贡献 optional 项。达到阈值即触发一次，无法达到阈值则提前失败。达到阈值不会取消其它活动分支或屏蔽其故障；任一已激活分支失败仍使 Run 失败，Run 完成还需所有活动分支收敛。Join 必须列出准确的 Handoff ID；Join 目标端口不允许游离入边。

Join 的一次性 `baseMapping` 用于公共输入，只能读取 `$.run.*`、通过同 Loop Scope 支配检查的 `$.loop.previous.*` 或 `$literal`；不读取当前 Agent 输出或人工审核上下文。由此避免要求每条 Join 入边重复提供共同状态，也避免不同来源写入冲突。

这组语义覆盖“条件会签”和“固定人数/比例门槛”两类常见制度，无需另造 `all_active`。若未来需要“所有当轮实际激活的来源都到达，但只在完整候选集结束后结算”等不同规则，应以具体场景和状态机为依据重新评审，而不是把模式名当作功能扩展入口。

### 将历史引用限制在紧邻上一轮的确定执行

`$.loop.previous.<agentId>` 仅指同一 Run、lineage 和 Loop Scope 中紧邻上一轮的唯一成功执行。控制流支配分析必须证明所有到达引用点的路径都已经过该执行；若 Agent 在前一轮可能未执行或执行多次，编译失败，不回退到更早轮次。

锚点 Agent 的初始化必须进入同一 Loop Scope 并作为首轮唯一锚点执行。若初始化在 Loop 外，不能冒充 Loop 历史；初始状态应从 Run 输入显式映射。

这一限制避免条件跳过后读取陈旧值或对“上一轮”产生不同解释。更宽松的历史查询需要显式的版本、时间窗和缺失策略，不属于 v2 的映射语法。

### 只在可证明范围内做静态检查

静态分析只对文档声明支持的 Schema 子集和控制流性质给出证明。复杂条件、运行时媒体类型和不能静态证明的 Schema 约束必须有诊断，并在 Runtime 校验；不宣称任意 JSON Schema 蕴含、条件互斥或运行结果可被编译期完全证明。

编译器检查在 Agent 激活前完成，不调用模型。运行时数据校验、条件判断和 Agent 执行仍可能消耗计算资源；不能据此宣称整个流程“零 Token”或“零运行时风险”。

## 社会分工场景映射

| 场景 | 建议原语 | 关键边界 |
| --- | --- | --- |
| 财务必审，法务按金额条件参与，安全按涉外条件参与 | 条件 Handoff、required/optional 字段、`all_of`、汇总 Agent | 必审材料由保证到达来源提供；条件分支只提供 optional 材料；至少一份贡献到达 |
| 双盲同行评审或红蓝对抗 | 独立输入投影、静态并行分支、主编 Join、审核/返工 Loop | 只是不显式交叉传递信息；不提供匿名性、抗推断或防串通保证 |
| 固定人数的多轮博弈 | 角色专属输入、裁判/协调角色、有限 Loop、每轮显式结果 | 适合表达回合流程，不替代博弈理论求解，也不处理动态任意人数 |
| 法务、财务和技术材料汇总 | `all_of` 或 `quorum_of`、字段槽位合并、汇总 Agent、唯一 result | 参与方不直接并发写最终结果；由归口角色完成完整交付 |
| 高风险操作审批 | Agent 输出审核门、独立 timeout、批准/拒绝路由、受控 Artifact | 审批者身份与授权由控制面验证；超时失败关闭，不自动代签 |

## 后果

- Team IR 更容易静态检查、版本化和恢复，但不支持任意动态组队或运行时改图。
- 可选字段和条件跳过能够表达按需会签；required 项必须由保证到达的来源覆盖。
- 最终结果具有单一归口，多个贡献者先汇总再对外交付。
- 数据映射和 Artifact 白名单有助于最小权限，但需要单独的身份、保密级别和信息流策略才能形成强机密保证。
- 开放协商、政治关系、价值判断、法定授权和信任治理仍由人类及领域控制面负责。
