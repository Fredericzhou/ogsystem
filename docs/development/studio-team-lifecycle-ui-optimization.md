# OGS Studio 团队构建全流程页面优化与 Electron 桌面端架构方案

> **状态**：方案提议（Draft）
> **适用范围**：`apps/team-site` 前端架构、OGS Studio 全流程界面与未来桌面端打包
> **核心原则**：结构最优、避免过度设计（Zero Over-engineering）、Electron 桌面化就绪

---

## 一、 背景与设计目标

OGS Studio 是多智能体团队编排与构建的核心环境。在团队生命周期（**定义 -> 编排 -> 调试 -> 门禁 -> 挂载**）的演进中，存在以下典型体验瓶颈：
1. **跨页面视觉与容器跳跃**：设计画布（全屏通栏）与信息页/调试页（普通流容器）的内边距、滚动模型不一致；
2. **长文本与负边距破界隐患**：长 JSON、Prompt、Token 详情在特定视口下容易突破边框，负外边距滥用造成横向滚动条；
3. **关键操作与状态心智漂移**：版本状态（已发布不可变 vs 设计中草案）在各 Tab 展示位置不固定；
4. **缺少对桌面 App（Electron）的预见性架构**：全屏滚动依赖 Window Scroll，未隔离标题栏拖拽区域、本地快捷键与无边界视口。

### 核心设计目标
- **避免过度设计**：不重写现有稳定骨架，不引入大型 React/Vue 运行时或沉重状态机；依托现有 Vanilla JS + CSS 变量体系，以最小代码增量获得最大结构收益。
- **全流程一致性**：统一工作区顶栏、Tab 导航、版本状态常驻、单行状态栏与分层 Z-Index。
- **Electron 桌面端就绪**：自包含零 CDN、视口滚动严格隔离（No Window Scroll）、原生标题栏拖拽支持、快捷键友好。

## 二、 Electron 桌面端就绪架构规范（Desktop Readiness）

为了让现有 Web 界面能够无缝打包为跨平台桌面端应用（macOS / Windows / Linux），遵循以下结构准则：

### 1. 视口契约与滚动隔离（Strict Viewport Boundary）
```
┌─────────────────────────────────────────────────────────────┐
│ Window Titlebar (macOS 交通灯 / Windows 标题 - 40px, 可拖拽)│
├─────────────────────────────────────────────────────────────┤
│ Studio Workspace Header (团队名, 版本胶囊, 主操作 - 48px)    │
├─────────────────────────────────────────────────────────────┤
│ Studio Workspace Nav (Info | Design | Run | Release - 38px) │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│ Page Body (严格 100% 满高，禁用 Window 滚动条，内容区内卷)   │
│ [data-layout-scroll]                                        │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```
- **禁止 `window` 级别滚动条**：根节点 `html, body, #app` 强制 `height: 100vh; overflow: hidden;`；
- **子区域独立滚动**：所有滚动行为限定在拥有 `data-layout-scroll` 或明确 `overflow: auto` 的容器内（如左侧树、日志流、属性抽屉）；
- **macOS 原生交通灯区域适配**：
  ```css
  /* 预留桌面端无框窗口拖拽区 (Frameless Window) */
  .app-shell-header {
    -webkit-app-region: drag;
    padding-left: var(--desktop-traffic-lights-padding, 0);
  }
  /* 所有可交互控件必须声明 no-drag */
  .app-shell-header button,
  .app-shell-header input,
  .app-shell-header a {
    -webkit-app-region: no-drag;
  }
  ```

### 2. 离线化与自包含资源（Zero External Runtime Dependencies）
- 严禁在运行时依赖外部 CDN（如 Google Fonts、unpkg、cdnjs）；
- 字体均采用系统原生字体族：
  - 西文/通用：`system-ui, -apple-system, BlinkMacSystemFont, "Segoe UI", Roboto, sans-serif`
  - 代码/等宽：`ui-monospace, SFMono-Regular, "Cascadia Code", Menlo, monospace`
- 图标采用内置 Inline SVG 或纯 CSS 绘制，杜绝网络字体图标加载抖动。

### 3. 本地进程直连与 API 契约透明
- 在 Electron 主进程中以轻量 Node 子进程运行现有 `apps/team-site/server.mjs`，BrowserWindow 通过 `http://127.0.0.1:<ephemeral-port>` 加载；
- 前端无需修改 RESTful API 通信层，天然具备本地运行、低延迟与数据本地落盘的特性。

## 三、 Studio 团队构建全生命周期页面优化方案

### 阶段 1：团队仓库与全景发现（`/studio`）

```
┌──────────────────────────────────────────────────────────────┐
│ 团队仓库 (Team Repository)                     [+ 新建团队]   │
│ 筛选: [ 全部状态 ▼ ]  搜索: [ 输入团队名称/目标...       ]   │
├──────────────────────────────────────────────────────────────┤
│ ┌───────────────────────────┐  ┌───────────────────────────┐ │
│ │ 团队 A          v2·已发布 │  │ 团队 B          v1·设计中 │ │
│ │ 结构化交付研发团队        │  │ 自动化合规审核团队        │ │
│ │ 3 角色 · 4 流程           │  │ 2 角色 · 2 流程           │ │
│ │ [查看详情] [挂载到项目]   │  │ [继续编辑] [运行调试]     │ │
│ └───────────────────────────┘  └───────────────────────────┘ │
└──────────────────────────────────────────────────────────────┘
```

#### 体验优化点：
1. **状态明确分层**：
   - **已发布（Released）**：使用稳固绿色徽标，展示只读保护锁，明确标注“已就绪，可供项目挂载”；
   - **设计中（In Design）**：使用蓝色工作态徽标，突出“草案编辑中”，提供一键 `[继续设计]` 快捷路径。
2. **快速导入与模版派生**：
   - 增加简单的拖拽导入 `.json` / `.zip` 团队资产包入口，简化团队复用动线。

### 阶段 3：架构编排与资产设计工作台（`/studio/teams/:id/design`）

```
┌───────────────────────────────────────────────────────────────────────────────┐
│ 团队 A · v2 (草案)   [● 静态校验通过]              [保存草案] [启动调试] [前往发布]│
├───────────────────────────────────────────────────────────────────────────────┤
│ [Info] [★ Design] [Run History] [Release Gate]                                │
├───────────────────────────────────────────────────────────────────────┬───────┤
│                                                                       │ 属性  │
│                           画布主编辑视口                              │ 抽屉  │
│                 (严格高度 calc(100vh - 128px), 纯净画布)             │       │
│                                                                       │ 角色  │
│                                                                       │ 模型  │
│                                                                       │ 契约  │
├───────────────────────────────────────────────────────────────────────┴───────┤
│ 状态栏: ● 图谱已载入 · 4 角色 · 5 流转契约 · 无静态校验错误       [缩放 100%] [全屏]│
└───────────────────────────────────────────────────────────────────────────────┘
```

#### 体验优化点：
1. **视口空间最大化与零负外边距**：
   - 坚决杜绝 `margin-inline: -38px` 或 `width: calc(100% + 76px)`；
   - 工作台宿主容器直接设置 `width: 100%; height: calc(100vh - 128px); box-sizing: border-box; overflow: hidden;`，边缘规整贴合；
2. **单行状态栏（行高 ≤28px）**：
   - 状态栏保持单行弹性布局（`flex-wrap: nowrap; overflow: hidden; text-overflow: ellipsis;`）；
   - 左侧：静态校验结果 + 节点统计；右侧：图谱视口重置与缩放比例指示；
3. **分段式属性抽屉（Property Inspector Accordion）**：
   - 避免长表单一次性滚到底，划分为三大折叠面板：
     - `01 基础职责`（名称、角色标识、职责描述）
     - `02 模型与算力`（主模型选择、降级回退 Fallback 模型、凭据探测状态）
     - `03 交互契约与上下文`（输入/输出 JSON Schema、下游 Handover 路由规则）
4. **即时定位问题面板（Problems Drawer）**：
   - 状态栏报错时（如未绑定模型、死循环连线），点击即可从底部滑出紧凑诊断列表，点击条目自动将画布视野平移聚焦至问题节点。

### 阶段 4：隔离调试与仿真回放（`/studio/teams/:id/run/:simulationId`）

```
┌───────────────────────────────────────────────────────────────────────────────┐
│ ← 团队 A / 调试详情 · 仿真任务 #sim-401                  [查看产物] [重新运行]│
├───────────────────────────────────────────────────────────────────────────────┤
│ 运行时长: 12.4s  │  完成角色: 3/3  │  节点流转: 4 次  │  消耗 Token: ~1,420    │
├──────────────────────────────────────┬────────────────────────────────────────┤
│ 节点执行流水 (Timeline Log)          │ 只读图谱流转联动 (Active Graph Focus)  │
│ ┌──────────────────────────────────┐ │ ┌────────────────────────────────────┐ │
│ │ 角色 A · 需求分析 (已完成)       │ │ │                                    │ │
│ │ 输入: 用户原始需求任务           │ │ │      [角色 A] ──> [角色 B]         │ │
│ │ 输出: 结构化 PRD 文档            │ │ │                    │               │ │
│ ├──────────────────────────────────┤ │ │                    ▼               │ │
│ │ 角色 B · 架构设计 (当前高亮)     │ │ │                 [角色 C]           │ │
│ │ 输出: 系统契约定义...            │ │ │                                    │ │
│ └──────────────────────────────────┘ │ └────────────────────────────────────┘ │
└──────────────────────────────────────┴────────────────────────────────────────┘
```

#### 体验优化点：
1. **画中画/分屏联动调试模式（Canvas-Timeline Bi-directional Sync）**：
   - 放弃“纯长页面纵向堆叠”模式，采用“左侧时序与流水 + 右侧图谱高亮”分屏布局；
   - 点击左侧流水中的某一步，右侧图谱自动聚焦对应角色并高亮上游流动光效；
2. **长文本与结果防爆规范（全面实施）**：
   ```css
   .project-panel pre,
   .run-result-card pre,
   .run-output {
     box-sizing: border-box;
     max-width: 100%;
     overflow-wrap: anywhere;
     word-break: break-word;
     white-space: pre-wrap;
   }
   ```
3. **QQ / 企业工作群聊式气泡交互与角色头像徽章（Workgroup Chat & Backend Badge）**：
   - **Role 头像与 Backend 模型徽章**：
     - Role 头像严格保留各角色定义的主题固有色（`--role-accent` 边框与 Monogram 文字，`--role-fill` 柔和底色）；
     - 当在 Inspector 为 Role 绑定了 Model Backend（如 Codex、Claude Code、Gemini CLI、Ollama、Qwen Code、Kimi CLI 等）时，头像右下角自动叠印该 Backend 的专属图标徽章（14px 圆形角标）；在设计资产抽屉与调试群聊中全局统一展示；
   - **群聊对话气泡排版（Chat Bubble Style）**：
     - 彻底摒弃单调的折叠框，重构为类似 QQ / 企业工作群的对话气泡布局：左侧头像（含模型徽章）+ 发送者角色名称（采用 Role 专属色）+ 消息气泡主体；
     - 消息气泡（`.team-debug-bubble`）具有专属圆角（`3px 12px 12px 12px`）、柔和底色与细阴影，直观呈现多智能体协作交流；
   - **下游角色 @ 联动（Downstream Role @-Mentioning Handover）**：
     - 当一个 Role 完成本环节任务后，系统依据 Flow 连线拓扑自动在气泡末尾生成 `@下游角色名称 [请接力协作 · Flow契约说明]` 提及药丸；若直连终止节点则提示 `@结束节点 [已达成交付]`；
     - 点击 `@下游角色` 可在图谱与面板中快速高亮聚焦目标节点与连接连线；
   - **图谱与流程调试降噪（Clean Canvas & Flow Diagnostics）**：
     - 清理调试时画布中多余/不和谐的临时图标杂质（去除节点上突兀重叠的齿轮/沙漏等干扰图形），图谱保持纯粹的呼吸光环与粒子流，重点由工作群聊面板直观传达多智能体协同效果。
4. **抽屉式产物浏览器（In-context Artifact Drawer）**：
   - 点击“查看产物”时，从右侧滑出文件树与代码预览抽屉，不破坏当前调试详情视窗上下文。

### 阶段 6：模型服务与运行底座联动管理（`/platform/models`）

```
┌──────────────────────────────────────────────┬─────────────────────────────────────────────────┐
│ 运行底座 (发现到的服务)                      │ 模型目录 (发现到的模型)   [按服务(激活) | 仅可用] │
├──────────────────────────────────────────────┼─────────────────────────────────────────────────┤
│ [★ Codex CLI] (已选中, 可运行)               │ 目录 · Codex CLI (2 个模型)                     │
│ · 运行底座已就绪                             │ ┌─────────────────────────────────────────────┐ │
│                                              │ │ gpt-5 · [可运行]                            │ │
│ [  Ollama Local] (可运行)                    │ │ 验证成功，12 ms · 文本输入 · 文本输出 · 工具 │ │
│ · 运行底座已就绪                             │ ├─────────────────────────────────────────────┤ │
│                                              │ │ gpt-5-mini · [可运行]                       │ │
│ [  Kimi CLI] (未安装)                        │ │ 验证成功，8 ms · 文本输入 · 文本输出        │ │
│ · 未检测到本地 CLI                           │ └─────────────────────────────────────────────┘ │
└──────────────────────────────────────────────┴─────────────────────────────────────────────────┘
```

#### 体验优化点：
1. **服务与模型主从联动（Master-Detail Linkage）**：
   - 默认模式下，“发现到的服务”与“发现到的模型”形成联动；
   - 点击左侧任一服务（如 Codex、Ollama、OpenCode 等），右侧模型面板即刻过滤展示该服务专属发现的模型；
   - 选中的服务条目具备明确的高亮轮廓和可访问性标识（`.is-selected`、`aria-selected="true"`）；
   - 面板副标题（Kicker）动态展示当前选中的服务名与模型总数（如 `模型目录 · Codex (2)`）。
2. **双模展示开关（按服务 / 仅可用）**：
   - 在模型目录面板顶部提供原生分段胶囊切换器（Segmented Toggle）：
     - **按服务 (By Service)**：专注于特定服务底座的模型配置，点击左侧服务即可实时切换；
     - **仅可用 (Available Only)**：跨底座全局汇总所有通过可用性探测（Live Probe Runnable）或可用状态的模型，方便角色配置与算力核对。
3. **交互手感与移动无障碍规范**：
   - 支持键盘快捷访问（<kbd>Enter</kbd> / <kbd>Space</kbd> 触发服务选择）；
   - 满足触控目标尺寸与无障碍属性（`data-touch-target-exempt` / 44px 移动端规范），响应即时无刷新。

## 四、 核心设计 Token 与交互层级规范

### 1. Z-Index 分层阶梯表
| 层级代号 | `z-index` 值 | 允许使用的组件 |
| :--- | :--- | :--- |
| **Canvas** | `1` | 图谱画布背景、网格、节点底图 |
| **Canvas Controls** | `2` | 画布缩放工具栏、小地图、常驻底部状态栏 |
| **Floating Panes** | `10` | 属性检查器（Property Inspector）、诊断抽屉（Problems Drawer） |
| **Docked Panes** | `20` | 吸附固定的调试控制板、侧边参数板 |
| **App Header / Nav** | `50` | 桌面端全局顶栏、工作区 Tab 导航条 |
| **Global Overlay** | `100+` | 模态弹窗（Dialog）、产物全屏预览、Toast 通知 |

### 2. 桌面端快捷键映射（Keyboard Shortcuts）
为 Electron 桌面操作预设原生交互心智：
- <kbd>Cmd</kbd> / <kbd>Ctrl</kbd> + <kbd>S</kbd>：立即保存当前设计草案（阻止浏览器默认网页保存）；
- <kbd>Cmd</kbd> / <kbd>Ctrl</kbd> + <kbd>Enter</kbd>：快速触发独立调试（Debug Run）；
- <kbd>Esc</kbd>：关闭当前打开的浮动抽屉、问题面板或弹窗；
- <kbd>Cmd</kbd> / <kbd>Ctrl</kbd> + <kbd>0</kbd>：画布视图复位（Zoom Reset 100%）。

## 五、 实施计划与里程碑

```

· 状态栏单行化与层级收敛  · 全局 Window 滚动条禁用     · 产物抽屉式速览            · 本地构建与安装包产出
```
