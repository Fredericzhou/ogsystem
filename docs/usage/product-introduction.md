# OGSystem 产品简介

OGSystem 把一组有明确职责的角色组织成可执行、可恢复、可审计的协作流程。普通用户从团队和项目开始，
工程人员可以继续使用 CLI 和专业工作台检查结构、契约和运行证据。

## 产品如何分工

- **团队**描述“谁负责什么、如何交接、如何协作”。团队是静态、可发布、可版本化的协作结构，循环、分支和
  汇合语义也属于团队定义。团队可以通过自然语言创建，再由人工或专业工作台微调，
  发布后进入团队仓库。
- **协作项目**描述“这次工作在哪里完成、使用哪些团队、要完成哪些任务”。一个项目绑定一个项目工作目录，
  可以挂载多个团队并产生多次任务运行；每次任务运行都有自己的运行工作目录。
- **任务运行**描述“本次具体要做什么、由哪个团队版本执行、结果如何”。一次任务运行绑定一个运行工作目录；
  输入、轮次、状态、反馈和运行快照都会保留，便于继续、审核和追溯。产品界面的“任务”当前就是任务运行记录，
  API/代码中的 canonical term 是 `Run`。
- **平台配置**负责发现本机的 Codex、OpenCode 和模型，并设置默认执行方式；不接管这些底座的账号和凭据。

团队建设与项目执行是两条独立路径：编辑团队不会创建项目，创建项目也不会修改团队结构。项目只挂载已发布
版本；需要调整团队时，应回到团队工厂另存为新版本。

## 任务控制

当前同一项目最多一个任务运行处于处理中、暂停或待人工审核状态。暂停可以继续，待审核可以提交通过、退回
或终止意见；任务运行完成或终止后，才能启动下一项。任务运行操作采用幂等处理，重复提交不会重复执行。

## 运行时能力

框架提供受限流程结构、角色执行、分支与汇聚、循环、异常路由、人工审核、检查点恢复和审计记录。运行状态
保存在 `.ogs/runs/<run-id>/`，恢复前会检查状态快照、会话索引和语义指纹的一致性；不一致时会拒绝猜测性恢复。
