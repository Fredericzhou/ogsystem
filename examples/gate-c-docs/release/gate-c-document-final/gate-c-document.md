# OGSystem v2 Artifact Workflow

## Purpose

This guide records the supplied documentation request and its review basis. It produces a concise, usable artifact without adding subject-specific sources or external citations.

## Workflow

1. Research the request and use only facts supplied in the request and outline.
2. Draft a concise document covering the objective, scope, evidence basis, and review status.
3. Declare the output file as a business document in Markdown with UTF-8 encoding.
4. The Runtime verifies declared files before sealing an Artifact.

## Evidence

- The request asks for research, a concise draft, and a final reviewed artifact.
- No subject-specific documentation, source materials, or external citations were supplied.
- The required output is represented as one JSON object with `event`, `content`, `data`, and `artifacts`.
- The declared file is `gate-c-document.md`.

## Acceptance

The artifact is accepted when it is concise, factually traceable to the supplied request and outline, free of invented sources, and present at the declared path with the requested Markdown metadata.
